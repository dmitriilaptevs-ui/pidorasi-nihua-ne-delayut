# rubai — три интерфейса первого запуска

Локальная рабочая итерация: выбранный дизайн **«Холст»** (`/canvas`). Общие OAuth, каталог и форма первого запроса. Ранее в итерации были ещё «Поток» (`/flow`) и «Импульс» (`/pulse`); они удалены по решению владельца (см. [DECISIONS.md](../../docs/DECISIONS.md)).

Не production-MVP: нет платежей, платных моделей, постоянной базы аккаунтов и выдачи production API-ключей. Старый ZIP не используется. [Объём и ограничения](../../docs/ONBOARDING-LAB.md).

## Быстро посмотреть дизайн

Требуется Node.js **22.19+** и npm. В каталоге `apps/web`:

```bash
npm ci
npm run setup
npm run dev
```

Откройте <http://127.0.0.1:3001/canvas> (корень `/` перенаправляет туда).

Без credentials работает интерфейс и чтение публичного каталога; OAuth и отправка AI-запроса явно недоступны. Приложение не показывает вымышленные ответы или «демо-вход». Для проверки полного сценария используйте следующий раздел.

## Подключить настоящие интеграции локально

### 1. Настройки

`npm run setup` создаёт **скрытый** `.env.local` с правами `0600` и случайным `SESSION_SECRET`. Существующий файл не перезаписывается. В файловом менеджере скрытые файлы видны после **Ctrl+H**. Все значения остаются на вашем устройстве.

Заполните `.env.local` по комментариям в [.env.example](.env.example):

| Переменная | Значение |
| --- | --- |
| `APP_ORIGIN` | `http://localhost` для общего адреса с VK ID |
| `SESSION_SECRET` | Создаётся setup-скриптом; не коммитить и не публиковать |
| `VK_CLIENT_ID` | ID зарегистрированного web-приложения VK ID |
| `VK_APP_TYPE` | `public` или `confidential`, строго как в кабинете VK |
| `VK_SERVICE_TOKEN` | Сервисный ключ для confidential-приложения; только на сервере |
| `YANDEX_CLIENT_ID` | ID зарегистрированного web-приложения Яндекс ID |
| `YANDEX_CLIENT_SECRET` | При необходимости; PKCE используется всегда |
| `OPENROUTER_API_KEY` | Отдельный ограниченный серверный ключ для тестирования |
| `OPENROUTER_FREE_MODELS` | Необязательный список согласованных ID через запятую; иначе все подходящие `:free` записи каталога |

Не использовать `NEXT_PUBLIC_*` для секретов. Не помещать конфигурацию в GitHub, чат, скриншоты или browser localStorage. После изменения credentials перезапустите dev-server, чтобы применить их однозначно; старые сессии завершатся.

### 2. Кабинеты OAuth

- **VK ID:** базовый домен `localhost`; trusted redirect URL `http://localhost/api/auth/callback/vk`; базовый scope `vkid.personal_info`. Для confidential-приложения указать сервисный ключ и разрешить реальный исходящий IP backend, включая влияние уже настроенного сетевого прокси. Не менять тип приложения лишь ради обхода проверки.
- **Яндекс ID:** redirect URI `http://localhost/api/auth/callback/yandex`; право `login:info`. Приложение должно быть включено и доступно для тестового пользователя.
- Адреса должны точно совпадать с запросами. Нельзя использовать для VK `localhost:3001`: текущая официальная инструкция ограничивает локальную разработку портами 80/443.

Реализован server-side Authorization Code + PKCE, не устаревший implicit flow. Callback — серверный redirect без HTML/JS; проверяются одноразовый `state`, browser-binding и `device_id` для VK.

### 3. Временный адрес localhost:80

Сам Next.js **не запускайте от root**. Он слушает только `127.0.0.1:3001`.

В отдельном терминале, после просмотра [кода прокси](scripts/local-proxy.mjs):

```bash
# Linux: из apps/web, пока npm run dev работает в первом терминале
sudo "$(command -v node)" scripts/local-proxy.mjs
```

Прокси открывает только `127.0.0.1:80`, сразу сбрасывает root-права до исходного пользователя и пересылает TCP на фиксированный порт 3001. Не ведёт request/access logs, не меняет firewall, не добавляет сервис или автозапуск. **Ctrl+C** завершает его. Если порт 80 занят, скрипт не останавливает чужой сервис.

Теперь откройте **<http://localhost/canvas>** — не адрес с портом 3001. Для HTTP на loopback cookie не имеет флага Secure; это исключение исключительно для локальной разработки. Используйте отдельный тестовый профиль браузера: cookies localhost не изолированы по портам.

### 4. Проверить полный сценарий

1. Нажать «Начать бесплатно», выбрать VK ID или Яндекс ID и самостоятельно подтвердить вход у провайдера.
2. После возврата убедиться, что показано имя и поле первого запроса.
3. Выбрать бесплатную модель, ввести небольшой несекретный текст и подтвердить его передачу OpenRouter/поставщику.
4. Отправить один запрос, проверить настоящий ответ, request ID и токены.
5. Выйти, проверить невозможность отправки без сессии. Повторить вход с другим провайдером.

На 2026-10-04 настоящий вход **VK ID** проверен на публичном приложении при запуске на `http://localhost`. Вход **Яндекс ID** и live-инференс ещё не проверены: их credentials не заданы. Наличие кода или успешных тестов с подменённым HTTP не является таким подтверждением.

## Защита бесплатного маршрута

- Сервер загружает публичный каталог OpenRouter; нет встроенного фиктивного списка моделей. Все используемые записи заканчиваются на `:free`, поддерживают text и имеют ровно нулевые значения всех объявленных ценовых компонентов.
- Перед генерацией каталог проверяется заново. Дополнительно задаются `max_price` = 0 и `allow_fallbacks: false`.
- Только один текстовый user-message, максимум 2000 символов и 600 output tokens; произвольные upstream-параметры, tools/plugins, URL, платные fallback и автоматические retries запрещены.
- Нужна сессия, точный same-origin POST и `consent: true`. Клиент не получает OpenRouter key или OAuth tokens.
- Локально: 3 запроса/минуту на пользователя, 20/сутки на всё приложение, до двух одновременных запросов (не более одного на пользователя). Ошибочные отправки тоже расходуют локальный лимит. OpenRouter может устанавливать более строгие квоты.
- Если разобранный успешный ответ не подтверждает `usage.cost: 0`, новые генерации приостанавливаются до проверки конфигурации и перезапуска. Это аварийная защита, **не финансовая сверка MVP**.
- Нельзя считать прерывание или timeout доказательством, что upstream не выполнил запрос. Приложение не повторяет его автоматически.
- Промпты/ответы не пишутся в логи, БД или browser storage; живут в памяти страницы до её закрытия/перезагрузки/выхода. Поставщики могут обрабатывать и хранить данные по своим условиям — не отправляйте личные данные и секреты.

## Сессии и границы локальной версии

Сервер хранит временные OAuth-handshakes (10 минут) и сессии (1 час) в ограниченной process-local памяти. Cookie содержит случайный opaque token; lookup — по HMAC. VK access token временно хранится только в серверной памяти для best-effort logout; refresh tokens не сохраняются. Аккаунты VK/Яндекс не склеиваются по email.

Перезапуск завершает сессии и сбрасывает локальные лимиты. Это **не** многорепличная auth-система, не постоянная регистрация и не production-защита от злоупотреблений. Production потребует БД/Redis, политики отзыва/блокировки/хранения данных, TLS, финансового контура и закрытых условий этапа 0. `APP_ORIGIN` намеренно запрещает нелокальные адреса.

Если на устройстве уже настроены `HTTPS_PROXY`/`HTTP_PROXY`, сервер учитывает их через `EnvHttpProxyAgent` с `NO_PROXY`. Адрес и credentials прокси не публикуются; TLS-проверка не отключается. Это использование существующей сетевой конфигурации, не настройка обхода ограничений поставщика.

## Проверки

```bash
npm test            # unit/security tests; внешние вызовы подменены в тестах
npm run typecheck
npm run build

# В отдельном терминале должен работать npm run dev (или npm start после build):
npm run test:e2e     # Chromium, desktop + mobile; ВСЕ API подменены только тестом
```

Если Chromium ещё не установлен: `npx playwright install chromium`. E2E не требует ключей, не совершает реальный OAuth и не отправляет запросы моделям. Настоящий каталог отдельно проверен в браузере; результат актуален только на момент проверки.

Результаты итоговой проверки этой итерации фиксируются в [ONBOARDING-LAB.md](../../docs/ONBOARDING-LAB.md).
