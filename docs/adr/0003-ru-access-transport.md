# ADR-0003: Публичный вход для пользователей из РФ без VPN

**Статус:** открыто — решение принимается по результатам измерений (задача `ru-access`).
**Контекст:** ноутбук в РФ за NAT, TCP вне VPN-туннеля блокируется kill switch, входящих портов нет. Значит, публичный вход возможен только через исходящий туннель к публичной площадке либо через отдельный публичный хост.

## Кандидаты

| № | Вариант | Плюсы | Риски |
| --- | --- | --- | --- |
| 1 | Tailscale Funnel на ноутбуке (`dima-laptop.tail4a5896.ts.net`) | Уже установлен, бесплатно, TLS из коробки, исходящее соединение | Доступность `*.ts.net` и Tailscale из РФ; лимиты Funnel; доступность ноутбука |
| 2 | Cloudflare Tunnel (quick tunnel `*.trycloudflare.com` или именованный туннель) | Бесплатно, публичный HTTPS без входящих портов, устойчивый edge | Эфемерный URL у quick tunnel; фильтрация Cloudflare в РФ; доступность ноутбука |
| 3 | Публичный VPS во Франкфурте (аренда) | Постоянный IP, DE-egress без Happ, нет зависимости от ноутбука | Платно (≈4–6 €/мес), нужно согласие владельца |
| 4 | РФ-фронт (Selectel/Yandex Cloud) + шифрованный туннель до DE-выхода | Домашний IP, устойчивость к реестру | Платно, два контура, сложнее эксплуатация |
| 5 | Альтернативные транспорты (WebSocket/HTTP-2/3, domain fronting) | Обход SNI-фильтров | Хрупкость, вопросы ToS |

## Метод оценки

- Измерения: доступность и задержка с потребительского устройства владельца в РФ, стабильность TLS и streaming, поведение при блокировке домена.
- Дополнительно: проверка доступности `ts.net` и `trycloudflare.com` из РФ.
- Критерии: воспроизводимость, отсутствие платной зависимости без согласия владельца, эксплуатационная простота, наличие fallback.
- Fallback и rollback описываются до переключения публичного трафика.

## Измерения (2026-10-05)

| Вариант | Проверка | Результат |
| --- | --- | --- |
| Cloudflare Tunnel (quick) | cloudflared 2026.9.3, `--protocol http2` и `quic`, edge-ip 4 и 6 | **Не работает** с этого хоста: TCP — `TLS handshake with edge: EOF`, QUIC — timeout; 1.1.1.1 при этом отвечает нормально |
| localhost.run | `ssh -R 80:localhost:3001 nokey@localhost.run` | **Работает**: публичный `https://<id>.lhr.life`, локально 200; владелец подтвердил открытие тестовой страницы с телефона в РФ без VPN; приложение отвечает через туннель (307 → /canvas, /api/status 200, POST с Origin туннеля не отклоняется) |
| Tailscale Funnel | `tailscale funnel --bg 3001`, tailscale 1.102.4 | **Не включён** в tailnet: CLI отвечает «Funnel is not enabled on your tailnet» даже после попытки владельца включить на `/f/funnel`; требуется повторно включить Funnel (и убедиться, что включены HTTPS-сертификаты tailnet) |
| Публичный VPS | — | Не арендован; требует явного согласия владельца на расходы |

## Текущее временное решение

Публичный вход для проверки — **localhost.run** (бесплатно, без входящих портов, подтверждён из РФ).

Ограничения и правила эксплуатации:

- Поддомен `*.lhr.life` выдаётся на соединение и меняется при переподключении SSH; при смене URL обновлять `PUBLIC_ORIGIN` в `infra/.env` и перезапускать `web` (`docker compose up -d web`).
- Стабильный постоянный адрес ожидается от Tailscale Funnel (`dima-laptop.tail4a5896.ts.net`) — предпочтительный вариант после включения, либо от собственного домена (вне текущего объёма).
- OAuth-провайдеры (VK ID/Яндекс ID) должны быть перерегистрированы на публичный адрес; до этого живой вход через публичный туннель не проверяется.

## Последствия

- Выбор фиксируется здесь после измерений; до этого публичный трафик не включается.
- Cloudflare исключён для этой площадки; возврат к нему возможен только с другого хоста/выхода.
