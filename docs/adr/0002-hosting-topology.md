# ADR-0002: Хостинг и топология развёртывания (MVP)

**Статус:** принято владельцем (2026-10-05), уточняет D-14.
**Контекст:** текущий сервер — выделенный хост Cherry Servers во Франкфурте (DE), одновременно рабочий стол владельца (Pi, Firefox, Docker-нагрузки, локальные приложения, loopback-прокси `127.0.0.1:80`). Публичного домена и TLS нет. Требование ТЗ R-03 (первичные данные в РФ) в MVP не выполняется.

## Решение

- Платформа (web + api + PostgreSQL + Redis + reverse proxy) размещается на текущем сервере в DE через Docker Compose.
- Публичный вход — временный хостнейм `sslip.io` до появления домена; TLS — ACME (Caddy или nginx+certbot). Порт 80 занят loopback-прокси — не останавливать его; использовать альтернативную схему ACME (DNS-01 либо освобождение loopback-порта по согласованию).
- Секреты — только server-side env-файлы `0600`/Docker secrets, вне git.
- Ресурсы ограничиваются (memory limits), стек не должен вытеснять рабочий стол.
- Отклонение от R-03 фиксируется здесь и остаётся решением владельца; перенос пользовательских/финансовых данных в РФ — отдельный этап.

## Последствия

- Нет резервирования и защиты от отказа хоста; backup/restore обязателен и проверяется drill-ом.
- Публичный сервис на машине с рабочим столом повышает риск: обновления и рестарты — только контейнеров, без перезагрузки хоста.
- Живые платежи и персональные данные юридических лиц в такой топологии не запускаются.
