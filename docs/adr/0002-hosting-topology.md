# ADR-0002: Хостинг и топология развёртывания (MVP)

**Статус:** уточнено 2026-10-05 по результатам проверки сети; заменяет первую редакцию ADR-0002.

## Фактическая топология (проверено)

- Ноутбук физически находится в РФ (часовой пояс Asia/Yekaterinburg, Wi-Fi `wlp0s20f3`, 192.168.0.15, за NAT домашней сети).
- Весь исходящий трафик по умолчанию идёт через интерфейс `happ-xray` (VPN-клиент Happ, Xray, запущен от root): публичный IP площадки — `88.216.74.34` (Cherry Servers, Франкфурт, DE). Kill switch блокирует TCP вне туннеля (ICMP проходит, TCP — нет).
- Входящего публичного доступа нет: NAT + kill switch. SSH до VPN-выхода отвечает, но ключи отклоняет; узел `ubuntu1` в tailnet офлайн.
- Tailscale установлен и работает: `dima-laptop.tail4a5896.ts.net`, владелец в tailnet — сам заказчик.
- PostgreSQL/Redis/Cloudflare/Caddy на хосте отсутствуют; Docker установлен, но пользователь `dima` не в группе `docker` (группа `sudo` есть).

## Решение

- Стек платформы (web + api + PostgreSQL + Redis) размещается на этом ноутбуке под управлением пользователя `dima`.
- Публичный HTTPS-вход обеспечивается **исходящим туннелем** из ноутбука (Tailscale Funnel и/или Cloudflare Tunnel), выбор — по измеренной доступности из РФ с устройства владельца (ADR-0003).
- Исходящие вызовы к OpenRouter идут через существующий туннель Happ → DE, поэтому провайдер видит зарубежный IP; страна клиента провайдеру не скрывается.
- Данные пользователей и финансовая база физически находятся на ноутбуке в РФ, что соответствует требованию R-03 по месту хранения; трансграничная передача промптов рассматривается отдельно (R-03).
- Секреты — только server-side env `0600`; TLS терминируется туннелем, локальные порты слушают только loopback.
- Docker используется только после одного интерактивного sudo-шага владельца (`usermod -aG docker dima`); до этого допустим запуск сервисов процессами пользователя.

## Последствия и риски

- Доступность продукта равна доступности ноутбука: сон, перезагрузка, Wi-Fi, обновления рабочего стола влияют на сервис. Публичный запуск 24/7 на этом хосте возможен только после проверки стабильности; отдельный VPS остаётся рекомендуемым следующим шагом.
- Порт 80 занят loopback-прокси `localhost:80`; стек использует другие локальные порты (например, 3001/8080), туннель публикует только HTTPS.
- Публичный сервис на машине с рабочим столом и Pi-сессиями требует аккуратности: перезапускаются только контейнеры/процессы стека, хост не перезагружается.
- Живые платежи и данные юридических лиц в такой топологии не запускаются.
