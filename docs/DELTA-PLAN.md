# План продуктовой доработки (дельта к ТЗ)

**Статус:** рабочий план текущей итерации. Фиксирует разрыв между прототипом `apps/web` и целевым продуктом из [ТЗ](SPECIFICATION.md) и [плана](ROADMAP.md), а также порядок работ. Не является отчётом о выполнении: отмечено только то, что проверено командами ниже.

Дата аудита: 2026-10-05. Ветка: `docs/hosting-topology-fix` (уточнение после `docs/productization-audit`).

### 1.1. Фактическая топология площадки (проверено)

- Ноутбук физически в РФ за NAT домашней Wi-Fi сети; весь исходящий трафик идёт через VPN-клиент Happ (`happ-xray`, публичный IP `88.216.74.34`, Cherry Servers DE); kill switch блокирует TCP вне туннеля.
- Входящего публичного доступа нет. Публичный HTTPS-вход — только исходящий туннель (Tailscale Funnel / Cloudflare Tunnel).
- Tailscale работает: `dima-laptop.tail4a5896.ts.net`; данных пользователей на DE-хосте нет — база будет физически в РФ (лучше для R-03, чем вариант с DE-хостом).
- Docker установлен, но `dima` не в группе `docker` — нужен один интерактивный sudo-шаг владельца.

- Контейнеризация начата: `apps/web/Dockerfile` (standalone) и `apps/web/docker-compose.yml`; compose публикует host-порт 80 и предназначен только для `localhost` (VK ID). Порт 80 на хосте уже занят loopback-прокси — одновременный запуск конфликтует.
- Нет: БД, пользователей, email+password, выдачи API-ключей, кошелька и журнала, gateway `/v1/*`, платежей, админки, публичного TLS.

## 3. Целевая структура репозитория

```text
apps/web   — Next.js: только интерфейс, обращается к API
apps/api   — FastAPI: identity, ключи, каталог, ledger, gateway, платежи
infra/     — Docker Compose, Caddy/nginx, backup/restore, systemd
docs/      — ТЗ, ADR, планы, отчёты приёмки
```

Переходный период: существующие BFF route handlers `apps/web` остаются рабочими до переноса identity в `apps/api`; после переноса cookie/сессии — на домене API или через прокси того же origin.

## 4. Порядок работ

1. **audit** — этот документ, ADR-заготовки, дельта-план. ✔
2. **infra** — стек на ноутбуке (Postgres, Redis, API, web) + публичный туннель (Tailscale Funnel и/или Cloudflare Tunnel), TLS, backup/restore, healthcheck; измерение доступности из РФ с устройства владельца. Требуется: один интерактивный sudo-шаг владельца (docker-группа).
3. **identity** — email+password (подтверждение, сброс, throttling), VK ID, Яндекс ID, сессии, RBAC, bootstrap администратора. Останавливается, если нет credentials Яндекс ID.
4. **keys-catalog** — выдача/отзыв API-ключей (hash-only), каталог моделей с рублёвыми тарифами и снимками наценки.
5. **ledger** — двойная запись в копейках, резервы, settle/release, сверка неизвестных затрат, идемпотентность.
6. **gateway** — `/v1/models`, `/v1/chat/completions` (JSON/SSE/tools), порядок auth → лимиты → резерв → upstream → usage → списание.
7. **payments** — YooKassa sandbox: создание платежа, webhook, ровно одно зачисление, возврат. Живые платежи запрещены (ADR-0004).
8. **frontend** — кабинет на дизайне «Холст», связка с `apps/api`, E2E desktop+mobile. Дизайн-решения — через `openai/gpt-6.1-sol`.
9. **ru-access** — ≥3 варианта доступа из РФ без VPN, измерения, ADR, выбранный вариант задеплоен. Платная инфраструктура — только с согласия владельца.
10. **acceptance** — матрица приёмки, security/load smoke, runbook, OpenAPI, handover.

Зависимости: 2 → 3 → {4, 5} → 6 → {7, 8}; 9 после 2; 10 последняя. Падающий тест блокирует следующий шаг.

## 5. Открытые вопросы и риски

- **Docker-доступ**: пользователь `dima` не в группе `docker`; для Compose нужен один интерактивный sudo-шаг владельца (`sudo usermod -aG docker dima`).
- **Нет входящего IP**: публичный вход — только туннель; доступность `ts.net`/`trycloudflare.com` из РФ надо измерить (ADR-0003).
- **Порт 80 занят** loopback-прокси `localhost:80` (VK ID); существующий `docker-compose.yml` web-приложения публикует 80 — публичный вход и локальная разработка разводятся по портам.
- **Память 7.6 ГБ**, свободно ~2 ГБ: стек должен быть ограничен по памяти; одновременно с рабочим столом и Pi.
- **R-03 (данные в РФ)**: база и пользовательские данные физически на ноутбуке в РФ; через DE проходит только исходящий вызов промптов к OpenRouter (трансграничная передача — отдельный вопрос).
- **Credentials**: нужны Яндекс ID и YooKassa sandbox; OpenRouter-ключ и VK есть.
- **Юридический контур** (этап 0) не закрыт независимыми доказательствами; публичные регистрации — на ответственности владельца, деньги — только sandbox.
